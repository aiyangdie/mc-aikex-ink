01 / TASK 1

口令由“立刻核爆”变成“连接级领取”

先写失败测试：改 tests/online-nuke.test.mjs：发口令后只收到 nuke_granted，500 ms 内无 nuke，快照生命/地形不变；重复输入仍只是一份能力；大小写错误不能领取；新 WebSocket 重进同房间无法直接投掷；另房间也不能继承。修改旧“口令即爆”断言，不是保留与新逻辑相冲突的旧测试。

运行红灯：node --test tests/online-nuke.test.mjs tests/room-chat.test.mjs，预期旧即时爆炸行为使新断言失败。

最小实现：server/server.js 的 chat 分支保持原有 sanitize、活跃/存活检查与速率限制，精确口令时只置 peer.nukeUnlocked=true 并向本 socket 回 {t:'nuke_granted'}，不向房间广播口令；连接/房间退出时清除能力。重复口令幂等。js/net.js 增加此事件分发。

绿灯与提交：重跑上述测试；git add server/server.js js/net.js tests/online-nuke.test.mjs && git commit -m 'feat: grant room-scoped nuke capability'。

02 / TASK 2

权威投掷、碰撞与原子核爆

先写失败测试：tests/nuke-projectile.test.mjs 用固定时钟验证弹体从服务端 peer 位姿发射、重力位移、首个实体地形碰撞、最长飞行时限；非法坐标字段被忽略，未解锁/死亡/非成员/冷却中拒绝；双投掷只生成一枚。tests/room-nuke.test.mjs 验证核爆使用可信落点而非玩家当前位置，跨维度死亡、仅落点维度挖坑、容量拒绝时生命/地形/冷却均不变。

运行红灯：node --test tests/nuke-projectile.test.mjs tests/room-nuke.test.mjs。

最小实现：新模块导出 beginNukeThrow(room,peer,now) 与 stepNukeProjectile(room,projectile,dt,now)；入口仅取 peer.x/y/z/yaw/pitch/dimension，有限值与世界边界检查后推导方向。服务器按现有房间 tick 频率推进，约 20 Hz；终端碰撞或 3 秒飞行上限触发结算。将 resolveNuke(room,caster,now,impact) 改成接受已验证 {dimension,origin}，先预检并应用地形，成功后才杀伤并落冷却；失败回滚预留冷却。施放者离线后保留 ownerId，落点结算时仅当前连接中同 id 者免疫，新连接不免疫。发射时占用冷却，期间拒绝第二枚。

绿灯与提交：通过两组单测；提交上述三个服务端文件与测试，信息 feat: simulate authoritative nuke projectile。

03 / TASK 3

房间协议与真实双客户端回归

先写失败测试：扩展 tests/online-nuke.test.mjs：领取→投掷→两端收相同弹体 ID/落点/nuke；受害者和 Boss 死，旁观房间无变化；重置地形仍有效；不带领取的重连投掷被拒；冷却中投掷拒绝但不清解锁。不要在网络测试里等待真实五分钟：冷却边界用单测注入时钟，真实 WS 只验证拒绝。

红灯：node --test tests/online-nuke.test.mjs。

绿灯与提交：网络测试通过；提交 feat: wire room nuke throw protocol。

06 / TASK 6

全链路验证、审查与 PR

  1. 运行 npm test，记录原始失败输出；核对 git diff --check。失败先定位，不为了过测绕开沙箱或删断言。
  2. 按 open-app-verify 启动并打开实际应用：双浏览器连接同房间与旁观房间，亲眼确认领取→持有→投掷→落点弹坑→死亡页→Boss 60 秒再刷、冷却、重连失权；近看广告文案，挖除与重置后变化。检查控制台和网络错误。
  3. 对照规格逐项自审：当前房间有效、无限次但受 5 分钟冷却、仅落点维度毁地形、施放者免疫、其他生灵跨维度死亡、普通炸弹与鼠标交互无退化。
  4. 仅在全部可验证项通过后推送功能分支至用户 fork 并创建/更新 PR；上游合并和部署须以实际权限与 CI 状态核实，不能把 PR 创建当作已合并或已部署。

REVIEW FOCUS

最可能漏掉的五种输入

  • 口令前后含空格或大小写变化：不授予；归任务 1 网络测试。
  • 同一人快速连续投掷与多个客户端并发：房间只接受一枚；归任务 2 单测及任务 3 WS 测试。
  • 投出后断线再重连：原弹体继续、重连无免疫/解锁；归任务 2/3。
  • 落点地形容量满或世界边界外：不发生部分死亡，冷却退回；归任务 2 单测。
  • 广告砖块在区块边界、挖除、重置、维度切换：无残留/重复贴片；归任务 5 单测与任务 6 浏览器验收。
执行前审阅点：这是一个耦合功能的分阶段计划，任务 1–4 共同构成核弹可玩闭环；任务 5 的广告贴花独立，可在核弹闭环后单独验收。若任一阶段改动导致已有测试失败，应停止推进并查旧逻辑冲突，不叠补丁。
