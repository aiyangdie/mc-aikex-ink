钻石矿微字广告

依据 docs/superpowers/specs/2026-09-23-diamond-ore-microtext-design.html。这份计划尚未执行；当前 PR 不因此自动更新。

目标：主世界每约 500 个自然实体方块有 1 个地下钻石矿；约四分之一的钻石矿可见面带小字；普通砖块不再展示广告。通过真实浏览器、服务端地形和联机同步验证。

全局约束：分母是主世界初次生成的非空气、非液体自然地形方块（不计树叶、玩家编辑与文字建筑）；矿石只能替换地下天然石头；生成 seed/坐标确定；旧 edits 优先；仅钻石矿约 25% 有字，原文严格为“激情大戏：spb.biily.top”；不发广告网络请求；不改安全/权限逻辑。

01 / TASK 1

确定性 1/500 地下钻石矿

步骤 1 · 红测试。新建 tests/diamond-ore.test.mjs：相同 seed/cx/cz/candidates 返回完全相同的坐标；换 seed 应变化；所有返回坐标均属于地下 STONE 候选且不重复；对至少 100 个普通地形区块统计 diamond/solid，预先设定允许区间 [0.0015,0.0025]，目标 0.002。追加断言：Nether/End 不生成钻石矿；既有 BlockType 0–15 不变，DIAMOND_ORE=16。

assert.deepEqual(selectDiamondOrePositions(input), selectDiamondOrePositions(input));
assert.ok(positions.every(p => candidates.some(c => sameXYZ(c,p))));
assert.ok(diamonds / naturalSolid >= .0015 && diamonds / naturalSolid <= .0025);

步骤 2 · 确认红灯。node --test tests/diamond-ore.test.mjs 应因模块/方块缺失失败；不得先写实现。

步骤 3 · 最小实现。在 js/diamond-ore.js 对 seed+区块坐标算稳定 hash，以 solidCount/500 的整数部分加确定性余数抽样确定矿石数，再按 hash 排序地下 STONE 候选取前 N 个。js/voxel.js 主世界正常地形完成基础方块、但生成树木之前，统计自然实体方块、收集位于表层至少 6 格以下的 STONE 候选并替换为钻石矿；中央特殊文字地形、地狱、末地不走此逻辑。追加方块 ID、名称、矿石底纹 atlas 槽；现有碰撞/挖掘/背包沿旧方块通路。

步骤 4 · 绿灯/提交。node --test tests/diamond-ore.test.mjs；npm test；git add js/diamond-ore.js js/voxel.js tests/diamond-ore.test.mjs && git commit -m 'feat: generate deterministic diamond ore'。

只给四分之一钻石矿贴微字

步骤 1 · 红测试。修改 tests/ad-decals.test.mjs：现有草地广告期望改为零；同一 seed/钻石坐标的带字资格稳定，换 seed 分布变化；跨大量矿石样本比率处于 [0.22,0.28]；非钻石方块带字严格为零；被挖除或遮盖无贴花，新外露面仍保留原矿的资格；不因局部编辑重抽剩余矿石资格。

REVIEW FOCUS

最易漏的输入

  • 地形种子相同但区块加载顺序不同：选矿位置不变（Task 1）。
  • 矿石处于 chunk 边界：邻块加载、挖掘或卸载后贴花不残留（Task 2/3）。
  • 旧存档的 AIR edit 盖在新矿石坐标上：不“长回去”，房间重置才复原（Task 3）。
  • 旧普通广告砖块：更新后必须归零，不可与钻石广告共存（Task 2）。
  • 微字变小后中文或域名糊成色块：近距真实浏览器截图必须可读（Task 3）。
容量与概率裁决：1/500 和 1/4 是大样本目标，不要求每个区块精确配额；测试用预设大样本区间，不凭一张截图判断比例。已有用户编辑永远优先于新基础地形。
