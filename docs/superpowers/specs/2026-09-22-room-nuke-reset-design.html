DESIGN SPEC · 2026-09-22 · REVIEW REQUESTED

联机核弹、地形重置与 Boss 再刷新

面向 mc-aikex-ink 的跨模块功能规格；此页是待用户审阅的设计，不代表代码已实现或生产环境已部署。

核心裁决：服务器是联机死亡、地形和房间权限的唯一裁决方；核弹只影响当前房间，输入者免疫；核弹毁地形，房主可确认后重置地形。Boss 死亡 60 秒后重生。

01 / AGREED OUTCOME

用户已确认的体验

触发结果边界
房间聊天输入 Maydaymayday除输入者外，本房间全部玩家与生灵死亡；输入者位置出现弹坑其他房间不受影响；只有完全匹配口令才触发
房主按“重置地形”并二次确认清空本房间所有方块改动，包括建设与核弹弹坑不重置背包、生命、Boss 倒计时或房间码
移动鼠标视角跟随，无需按住右键右键保留放置；聊天与确认对话框期间不转视角
Boss 死亡60 秒后本房间满血再刷包括被核弹击杀；原单机 Boss 亦按相同规则

02 / CHOSEN APPROACH

房间权威事件

采用服务器统一结算方案，不采用客户端各自爆炸（容易不同步与伪造），也不重做完整事件溯源系统（超出本次范围）。聊天事件、核弹事件、重置请求和 Boss 倒计时写入现有 Room/NetClient 边界。

聊天与核弹。桌面端按 T 打开聊天；回车发送，Esc 关闭。发送时输入框获得焦点，控制与镜头输入暂停；关闭后点击游戏区域恢复鼠标锁定。普通聊天广播给本房间，服务端限制长度、发送速率，客户端用 textContent 呈现，不把消息插入 innerHTML。完全匹配且大小写一致的 Maydaymayday 被当作命令，不公开口令文本，只广播核弹警报。命令只允许存活且已开始游玩的成员发送，服务器按房间记录上次核爆时间，每房间 5 分钟冷却；重启后冷却继续。
核爆结算。服务器记录施放者 ID、位置、维度和事件序号；把本房间其他在线玩家 HP 设为 0，进入手动复活流程，不受先前短暂无敌影响；施放者 HP/背包保持不变。清除服务器管理的普通生灵；Boss HP 归零并记录 respawnAt=now+60000。若当前维度有客户端本地实体（例如末影龙），同步核爆事件使该维度客户端清除对应实体；玩家和服务器实体的死亡仍以服务端状态为准。下一次加入须得到权威房间快照，不会复原已清除的服务器生灵。
弹坑。以输入者当前维度的位置为中心，半径 12 个体素；服务器按受限球形/碗形体积设置 AIR，尊重既有世界边界、方块改动上限与安全规则，不删除世界生成器或持久化层。广播压缩的批量 edits；客户端批量更新地形并只重建相关区块。房间存档保存弹坑。现有服务端 edits 不分维度，实施前须先扩展为按维度区分，并把旧数组迁移到主世界；不能把地狱/末地核爆写错到主世界。

03 / RESET & RESPAWN

权限与生命周期

房主权限。服务端保存房主 peer ID，而不以可改的昵称判定；原房主离开时明确移交给当前在房间内的下一位成员。仅房主能请求重置。客户端显示不可逆确认文案，服务端重新验证身份后原子清除所有维度的 edits，持久化并广播 terrain_reset；各客户端清空本地网络地形差分并重建可见区块，不能用旧本地存档再次上传覆盖。
Boss 再刷新。RoomBoss 的死亡时间戳/下一次刷新时间进入存档；每个房间独立计时，到点重新生成一个 1500 HP Boss 并广播状态。旧客户端模型必须销毁后重新载入/复用，不得堆重复 Boss。单机存档记录相同 wall-clock 时间；退出再进若已超过 60 秒直接刷新。重置地形不缩短此倒计时。
玩家死亡。核弹受害者看到死亡页和原因；点击重生后服务器恢复 20 HP 并给予 3 秒保护。普通 PvP 的已有自动复活行为继续独立运行。发起者免疫死亡，但仍看到爆炸效果。已死亡玩家不能再发送核弹口令。

04 / INPUT & VISUAL

沿用游戏现有像素 HUD

聊天层、房主确认按钮和核爆提示都延续当前游戏现有字体、边框和按钮，不另起视觉主题。核爆表现使用运行时粒子、闪光和震动，不生成新图片资产。桌面端优先 Pointer Lock，移动鼠标直接改视角；Pointer Lock 不可用时，在游戏画布内自由移动鼠标也可转视角，不要求按住右键，但光标碰到窗口边缘后的转动受浏览器限制。右键始终是放置。打开聊天/房主对话框时暂时释放或停用视角输入，避免输入口令导致角色移动。

保留风险：“所有生灵”跨维度和客户端本地实体必须用真实双客户端测试；仅广播视觉特效不等于服务端确认击杀。房主重置会抹掉所有人的建设，确认框必须写清楚。弹坑不能覆盖安全/沙箱规则。

05 / PROTOCOL & TESTS

边界与验收

Client → Server: chat{text}, nuke (由 chat 精确口令在服务端转换), terrain_reset
Server → Room: chat{by,text}, nuke{caster,dimension,origin,sequence,edits}, terrain_reset{revision}, boss{hp,respawnAt}
Snapshot: room hostId / terrainRevision / per-dimension edits / Boss respawnAt / nuke cooldown
  • 单测：口令严格匹配、5 分钟冷却、死亡玩家拒绝、施放者免疫、跨房间隔离、房主权限/移交、体素范围与数量、跨维度地形隔离、Boss 60 秒计时及存档恢复。
  • 双真实 WebSocket：两个房间，目标房间多玩家/生灵；触发核爆后服务器快照及两端一致，旁观房间不变；重置后重连仍是原地形。
  • 浏览器打开应用亲眼验收：无按键鼠标转视角、右键放置、T 聊天、核弹动画/弹坑/死亡页、房主二次确认与地形复原、Boss 60 秒再刷；检查控制台与网络错误。
