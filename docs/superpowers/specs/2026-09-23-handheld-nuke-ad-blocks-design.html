DESIGN SPEC · 2026-09-23 · REVIEW REQUESTED

手持核弹与广告砖块

针对现有联机核弹功能的行为调整与地图视觉增量。此页是待审规格，不代表代码已实现。

核心裁决：输入 Maydaymayday 只领取当前房间的无限次手持核弹，不立即爆炸。玩家主动投掷，服务器模拟弹道并在落点结算；房间仍有 5 分钟核爆冷却。部分可见砖块展示“激情大戏：spb.biily.top”。

01 / GAMEPLAY

领取、持有、投掷

动作预期边界
聊天发送完全一致的口令只给发送者解锁手持核弹，显示领取反馈；不造成死亡或地形变化仅联机、当前房间、当前连接；重复输入幂等
选择核弹并右键投掷出现手持与飞行模型；落地后爆炸核弹为独立虚拟装备，不占九格背包、不写入本地背包存档；保留既有普通炸弹
再次投掷道具不消耗，可以无限次使用房间核爆冷却未结束时禁止发射，HUD 显示剩余时间
离开／断线／重进房间核弹解锁失效，必须重输口令无账号、无跨房间继承

桌面端以独立核弹装备入口／快捷键切换到手持状态，右键沿用当前次要动作；移动端若已有触控操作区则提供等效可见按钮。切回普通物品不丢失解锁。打开聊天或对话框时不可误投。

02 / SERVER AUTHORITY

意图而非客户端爆炸坐标

客户端仅发送“投掷”意图。服务器再次检查房间成员、存活、解锁与冷却，以服务端角色位置／朝向推导投掷起点和方向，限制速度、距离和飞行时长；服务器更新弹道、检测地形碰撞并广播轨迹和落点。客户端动画只用于表现，不能提交爆炸位置或伤害。被接受的投掷即占用该房间 5 分钟冷却，以防并发重复发射；拒绝不消耗解锁。
首次碰到地形时爆炸；超过有限飞行时长仍未碰撞，则在最后有效位置爆炸，避免无限飞行。已发射弹体在施放者断线后继续结算；重连成为新连接，不继承免疫或解锁。服务器重启后保留既有房间冷却记录，不保留连接级解锁。
将现有核爆结算拆成“口令授予”和“可信落点结算”。施放者免疫；当前房间其余玩家、普通生灵与 Boss 跨维度清生命；只有落点所在维度生成半径 12 格弹坑。Boss 仍在死亡 60 秒后刷新。地形容量／安全规则校验失败时不得出现“生灵死了但弹坑没生成”的半结算；失败须广播原因并回退本次冷却。
兼容性：旧的“输口令即核爆”行为由此规格取代；房间隔离、重置地形、Boss 刷新、输入者免疫及沙箱安全规则保持。不得复用客户端自行结算的普通炸弹逻辑作为联机权威结果。

03 / AD BLOCKS

稀疏、可读、随地形变化

在确定性挑选的少量外露砖块表面绘制高分辨率像素风贴花，完整内容严格为 激情大戏：spb.biily.top。按种子、维度和方块坐标选择，所有客户端看到同一位置；只画外露面，不覆盖碰撞或方块材质规则。贴花使用运行时 Canvas 文字纹理和本机字体回退，不请求广告网络，也不可点击。

每区块数量设上限、按可视距离加载并释放纹理／网格；16×16 基础图集不直接承载整句文字，以确保近距离可辨认。方块被挖除则贴花消失，房间重置后按复原地形重建。若投影到单面无法清晰识别，则优先使用略高于表面的告示贴片，但仍附着于砖块，不悬浮成独立广告牌。

04 / ACCEPTANCE

必须验证的情境

  • 口令只解锁，不立即爆炸；大小写或多余字符不匹配；不能替别人领取。离房、断线和进入另一房间后必须重新领取。
  • 领取后可反复投掷；冷却中无法发射且显示倒计时；到期无需重输口令；两个房间冷却互不影响。
  • 双真实 WebSocket 客户端验证同一弹道／落点／弹坑；伪造坐标和未解锁投掷被拒；施放者免疫，其余房间成员与生灵死亡，旁观房间无变化。
  • 浏览器亲眼验证手持模型、切换装备、投掷动画和落点爆炸；广告原文近距离可读，挖除／重置同步，控制台无错误；不得仅凭单测宣称交互完成。
  • 回归：普通炸弹、右键放置、聊天输入、房间重置、Boss 60 秒再刷新、沙箱规则均不退化。
