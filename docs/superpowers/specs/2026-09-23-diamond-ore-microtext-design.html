DESIGN SPEC · 2026-09-23 · REVIEW REQUESTED

钻石矿上的微字广告

对现有随机地形与广告贴花的限定修改；这是待审设计，不代表代码已经实现或 PR 已更新。

用户目标：主世界随机生成钻石矿；按生成的实体地形方块计，平均每约 500 块出现 1 块钻石矿。约 1/4 的钻石矿表面印很小的“激情大戏：spb.biily.top”；普通砖块不再出现该广告。

01 / GENERATION

密度与世界一致性

规则具体定义
分母主世界区块初次生成的非空气、非液体自然地形方块；不计玩家后来放置的块、树叶与建筑文字方块。
分子钻石矿方块；以地下天然石头位置为候选，不在地表、树木、传送门、地狱或末地生成。
概率口径长距离统计目标为约 1/500，不要求每个区块或每连续 500 块恰好一块；区块边界与不同种子可有随机波动。
位置由世界 seed、维度和世界坐标确定；重载、不同联机客户端与服务端碰撞地图保持一致。地形重置回到该种子的同一矿脉分布。

优先在现有世界生成流程中加入一个独立 DIAMOND_ORE 方块类型与 16×16 矿石底纹，保留已存在方块类型编号，不重排旧编号。矿石在现有挖掘／背包流程中按矿石方块处理；本次不新增钻石装备、合成或交易玩法。

02 / MICROTEXT

只有钻石矿可带字

对钻石矿坐标做独立的确定性四分之一选择，目标为全部钻石矿约 25%，不因是否目前外露而改变资格。埋在地下时不渲染文字；挖开后有可见面才显示。贴花只附着钻石矿外露面，矿石被挖掉即消失，重置恢复。普通石头、泥土、木板、黑曜石等原广告候选全部取消。
文案严格为 激情大戏：spb.biily.top，不省略域名、不变成可点链接、不向该域名或第三方发请求。字区应明显小于整个方块面，例如居中的小铭文；正常探索距离不抢眼，玩家靠近时仍能读全中文与域名。沿用现有运行时文字纹理／像素视觉，不使用 AI 生图或远程资产。不能为了“字小”把中文渲染成不可辨认的几个像素。

03 / EXISTING WORLDS

编辑记录与房间

旧世界重新进入时，未编辑的自然地形按同一种子生成新钻石矿；用户已挖除或放置过的格子以现有 edits 为准，不被矿石生成覆盖。房间重置清空 edits 后，所有客户端恢复到同一种子的基础地形和相同的钻石矿／带字资格。矿石资格是视觉派生数据，不写额外存档，也不增加联机广播体积。

兼容约束：新方块必须被现有实体碰撞、破坏、背包、存档与同步路径识别；服务端自然地形与客户端一致。若服务端仅共享同一 World 生成模块，应通过现有共享路径生效，不维护一份独立、易漂移的矿石算法。不能动沙箱／权限校验。

04 / ACCEPTANCE

测试与亲眼验收

  • 跨多个 seed 与足够区块统计实体地形总数和钻石矿总数，验证比值围绕 1/500；统计误差阈值在实现计划中按样本规模明确，不把单区块波动当缺陷。
  • 对相同 seed、坐标、维度重复生成与重新入房，钻石位置一致；旧 edits（挖除／放置）优先，重置后复原。
  • 统计钻石矿的带字资格，目标约 25%；非钻石方块带字数严格为零；挖出新外露面时正确出现，挖掉矿石时消失。
  • 浏览器打开真实游戏，近看小字必须能完整读出文案，正常探索视距不出现大面积广告牌；钻石底纹与普通矿可区分。
  • 双真实客户端验证矿石与文字一致；服务端自然地形／碰撞一致；方块挖掘、背包、房间重置、核弹弹坑后贴花更新均不退化。运行完整测试并记录任何失败。
